## 1.3.2（2026-11-19）

**收尾帧改用 cmd 0x01 —— 打印后不再断连**

用户反馈"以前打印后不用重连"。实测查明：

* 用 `cmd 0x08`（提交帧）收尾 → 能打印，但固件**立刻断开 BLE**
* 用 `cmd 0x01`（状态帧）收尾 → **同样能打印，且连接保持**

于是全面切换默认收尾方式为 0x01：

* 库：`print_raw_image(terminator="status")` 成为默认
* CLI：`--terminator` 默认 `status`（可选 `commit` / `feed`）
* 两个网页：收尾帧从 `COMMIT_FRAME` 改为 `STATUS_FRAME`
* 打印服务：默认以状态帧收尾
* 实测：连续 2 次打印、100mm（38 帧）大图都完整，`is_connected` 全程 True

界面（上一版遗留）：

* 宽屏（≥1024px）改为左右两栏：左边操作、右边预览（预览 sticky）
* 修：预览图被 flex 的 `align-items:stretch` **纵向拉伸变形** → `flex-start`
* 修：连接状态条原来是整行等宽 → 改成自适应宽度的胶囊
* 修：手机宽度下按钮竖排、复选框文字被裁、调试页横向溢出

## 1.3.1（2026-11-18）

* **打印浓度默认改为 10**（官方 App 的默认值），三处入口统一：
  CLI `--density` 默认 10、网页「浓度」默认选中 10、打印服务 `/print` 不传也按 10
* 设备当前浓度已经是目标值时**跳过设置**（省一次 BLE 往返）
* 修：打印结束后固件会主动断开 → 恢复浓度前自动重连（否则静默失败，设备被留在临时档位）

## 1.2.0（2026-11-18）

**精简：删掉做不到 / 没用的东西**

* 移除 `--exact`（实测不能省尾部 7mm）及其在打印服务、两个网页里的开关
* 移除 `--terminator status|none`（与 commit 等效或更差），只留 `commit` / `feed`
* 移除 `--bmp-chunk`（>1024 固件不收）、`--batch`（无提速）、`--window`（>1 丢数据）、
  `--segment-mm`（分段产生 18mm 缝隙，已被单任务替代）、`--no-paginate`
* `paper.split_image`、`paper.EXACT_SAFE_FRAMES` 一并删除

**统一语义**

* CLI 的 `feed --mm N` 现在默认表示**纸总长**（与网页、打印服务一致），
  要内容长度用 `--content`
* 分页阈值统一为 1200 行（Python 与 JS 一致）

**新增（上一版的修复延续）**

* 按内容帧数**自动选发送节奏**：≤13 帧走快速路径（连续），更长走流控（完整但会顿）
* 提交前等最后一帧 ack（修截断）

## 1.1.0（2026-11-18）

真机（GT1 `00:15:83:E4:7A:F2`）验证的一轮，协议语义基本摸清。

### 新增能力

* **纸总长控制**：`--total-mm 40` / `{"totalMm":40}` —— 实测"要 40mm 出 40mm"
  * 固件每个任务固定多喂 **11mm（开始）+ 7mm（结束）= 18mm**，已做补偿
  * 内容高度仍可用 `--length-mm`（不含那 18mm）
* **打印浓度可调**：`0x02` = 浓度 1..10（默认 10）
  * 浓度越低 → 每行加热越久 → 打印越慢；慢速 BLE（~3 KB/s）下**长图才打得完整**
  * 网页「浓度」下拉框：打印前改、打完自动恢复
* **电量估算**：`0x04` = 电池电压（0.05 V/LSB），`battery_percent()` 换算百分比（±10%）
* **缺纸检测**：`0x06`（有纸 0 / 缺纸 1），双向验证；打印服务支持 `checkPaper` 预检（缺纸 409）
* **走纸**：空白位图按点数走纸（8 点/mm），`feed --mm N`；另有 `--total` 按纸总长
* **指示灯开关**：`0x03`（可读可写），网页「开灯/关灯」按钮
* **定时 / 重复打印**：打印服务 `POST /jobs`（`delaySec` / `at` / `repeatSec`），
  缺纸自动延后、失败重试 3 次、`--jobs-file` 落盘
* **中文强制走位图**：这台固件的 GBK 文本帧没有中文字形（汉字打出来是黑块），
  凡是含非 ASCII 的文本一律改走位图（CLI / 两个网页 / 打印服务一致）
* **cmd 0x08 = 提交帧**：让固件把已收到的位图打出来，且**不驱动电机**（比状态查询更语义化）
* **`--exact`（内容结束即停）**：不给结束信号，尾部 0mm；但内容必须 ≤13 帧（≈34mm），
  15 帧实测会出白纸
* CLI 新增 `--version`、`info`、`setting`、`feed` 子命令

### 修复

* **图片帧必须补"终结帧"才出纸** —— 这是"网页能打图、Python 打不出来"的真因
  * 终结帧可用状态查询帧（零走纸）或换行帧（走 N 行）
* 通知会被拆成多个 20B 分片 → 按 `AA/LEN` 重组（否则只能拿到半截帧）
* 订阅 notify 后第一包是上次连接的残留 → 每次发送前清空缓冲 + 重试
* Windows 下每个 GATT 写入有 ~50ms 固定开销 → 分片从 20B 提到 180B（快 2.4 倍）
* CLI `image a.png` 曾把文件名当文本打出去（位置参数撞车）

### 已知限制

* **不支持退纸**（单向纸路，12 条候选命令全试过）
* **电量只能估算**（固件不提供直接读数；负载重时偏低）
* **长图受 BLE 吞吐限制**：默认浓度 10 时约 25mm 就断；降到 5~6 可完整打印
* `0x05/0x06/0x07` 疑似 RGB 灯通道，**写 255 会让设备拒绝连接**（需断电重启），未摸清前不要写
* 自动关机时间**尚未确认**能否修改（`0x02` 已排除，它是浓度）
* **尾部 7mm 无法消除**（已穷举：状态查询帧 / cmd 0x08 提交帧 / 带参提交帧 / 去掉预热 /
  绕过白名单写 tag 0x07~0x12 全被忽略）。要 0 尾部只能用 `--exact`，且内容必须 ≤34mm
* 单任务上限 400 行（≈50mm），超过必须分页，页间有固件固定的 18mm 空隙
