## 2. 三种连接方式

### 2.1 BLE（`o0/g.java`）

```
Service   FF00  (0000ff00-0000-1000-8000-00805f9b34fb)
  FF01    notify   (properties & 0x10，排除 0x20)
  FF02    write    (0x04 write-no-response / 0x08 write)
  FF03    可选 notify（仅在特定固件上启用，用于额外通道）
CCCD      2902
```

兜底：别的模块用 `FFE0` 服务 + `FFE1` 特征值（HM-10 那类透传模块），
另外还认一个服务 `E7810A71-73AE-499D-8C15-FAA9AEF0C3F2`（其他厂商的打印机）。

写入细节（重要）：

* `setWriteType(1)` = **write without response**
* 分片：`min(剩余, MTU)`，某些机型强制 **≤20 字节**
* 有 **credit 流控**（`this.J` 计数，每写一片减一）—— 和我们给 GT1 做的"等 ack"是同一类保护

## 3. 协议帧格式（`com.dothantech.data.b`，已逐行核对）

**没有"结束字节"，最后一字节就是校验。** 而且两个方向帧头不同：

```
主机 → 打印机：  0xAA | CMD | LEN | PAYLOAD... | CRC
打印机 → 主机：  0xBB | CMD | LEN | PAYLOAD... | CRC
（老固件：两边都是 0x1F，`k()` 切老模式、`l()` 切新模式）
```

| 字段 | 规则 |
|---|---|
| 帧头 | 写：`f3254c`；读：`f3255d`。新模式 `0xAA` / `0xBB`，老模式都是 `0x1F` |
| CMD | 1 字节命令码；**CMD == 0 表示裸数据**（不加帧头，直接发 payload） |
| LEN | `< 192` 时 1 字节；否则 2 字节 `(0xC0 \| hi), lo` |
| CRC | `(~sum(bytes[1..len-1])) & 0xFF`（即 CMD..payload 求和取反） |
| 免校验 | 全局开关 `f3256e = true` 时，CRC 位置固定填 **`0x88`** |

对照源码（`data/b.java` 的 `m()`）：

```java
bArr[0] = f3254c;              // 0xAA
bArr[1] = cmd;
if (len < 192) { bArr[2] = len; payload 从 3 开始; crcAt = len + 3; }
else { bArr[2] = 0xC0 | (len >> 8); bArr[3] = len & 0xFF; payload 从 4; crcAt = len + 4; }
bArr[crcAt] = a(bArr, 1, crcAt);   // 校验覆盖 CMD..payload
```

解析侧（`n()`）除了认帧头，还会校验"整段求和为 0"，并对 `CRC == 0x88` 直接放行。

## 4. 已知命令码（从能力探测代码里提取）

`printer/a.java` 的初始化阶段会逐条探测固件能力，用的就是这些单字节命令：

```
0x7C 0x79 0x7A 0x75 0x7D 0x71 0x72 0x52('R') 0x57('W') 0x59('Y')
0x79 0x44('D') 0x9F 0x83 0x0A 0x29(')')
0x70('p') 0x84 0x43('C') 0x44('D') 0x42('B') 0x88
0x45('E') 0x47('G') 0x48('H') 0x49('I') 0x4D('M') 0x73('s') 0x7F
0x40 + [0x41('A'), 0x01, 0x02, 0xFF/0xFB]   ← 带子命令的复合包（0x40='@'）
0x77('w') + [0x00, 0x00]
```

这些不是 TSPL / ESC-POS / CPCL / ZPL —— 全仓库搜不到这些关键字，
是**德佟自有的私有协议**（标签文档格式是 `.wdfx`）。

## 6. 想真正控制它，下一步做哪个

| 路线 | 工作量 | 说明 |
|---|---|---|
| **A. 抓包还原**（推荐） | 中 | 手机开"蓝牙 HCI 日志"（开发者选项）或安卓上用 btsnoop 抓一次真实打印，按 `AA…BB` 解帧，对照命令码即可复现 |
| B. 直接调用其 SDK | 小 | 它本身就是 AAR（`com.dothantech.printer`）；写个安卓小程序调 `IDzPrinter` 打印，比自己实现协议省事 |
| C. 纯静态推完命令集 | 大 | 要读完 195KB 的 `printer/a.java` + `BitmapPackage`，把"文字/条码/位图"每条命令的载荷格式逆出来 |

抓包时注意对齐我们已有的经验：

* 写用 **write-without-response**，分片 ≤20 字节起步
* 有 credit/ack 流控，发送太快会丢数据（GT1 上踩过）
* 结束要发"提交/结束"包，否则不出纸
